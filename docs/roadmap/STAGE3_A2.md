# Stage3 foundation: A2 deterministic input replay

Status2026-11-02: **A2 software foundation passes**, before replay-dependent exercises/tools. This checkpoint is not a completed Stage3 feature pack or a deployment. Production remains09.01. I9 highlight seeking is now connected to actual compatible replays.

Recording wraps the existing Simulation authority: ordered delivered look deltas, consumed120Hz input, settings/weapon/reset/retry/input-clear commands, submitted target frames with tick/interpolation/time, and final external run/completion flags. Frame reconstruction repeats the renderer's exact matrix arithmetic rather than storing outcomes or video. Tracking and click-selected older displayed frames therefore follow the same history. No smoothing or recording compression is added to immediate mouse handling.

Playback constructs a fresh seeded Simulation, executes those commands and checks state digests every120ticks and at completion. Digests cover movement/contact/jump timers, weapons/recoil/RNG, target generations/health/RNG, defender decisions/death/retry, footstep/landing state, tracking, shots, score and rendered-frame authority. UUID/creation time and display-only THREE resources are excluded. Checksums are reproducibility checks, not cryptographic authentication; score verification reruns commands.

Measured one-minute fixture: **7200ticks,60,000look events,3600displayed frames,70,801commands**, about906kB JSON and **134,241gzip bytes**, below200kB. Repeated execution produces identical state/outcome digests. This size is a defined fixture result, not a guarantee for arbitrary high-entropy input or constant setting edits. Recording limits are explicit:30minutes,750,000commands,2MB compressed and24MB decompressed; recording failure leaves ordinary training usable and reports the missing replay.

Actual combat fixtures reproduce a legitimate rendered-frame headshot/elimination and a defender kill with paused-clock debt and same-map retry. All four weapons, both movement families, all existing timed modes, configuration transitions, scoped behavior and final-tick markers are covered. Import tests reject unknown commands/schema, invalid axes, prototype keys, malformed gzip, oversized streams and changed result cards. Compatibility pins game/simulation/movement/projection/calibration versions.

An actual App→Runtime→BrowserInput→IndexedDB browser session passes7 checks: real PointerLock training, saved recording, result replay verification, gzip export, history library, re-import and verification without locking viewer input. Its exported recording is15,330bytes and contains a real elimination. The browser integration exposed a mutable-input alias: Movement now stores only its intended walk/crouch sample rather than the browser's reused entire input object. Unlock resets can no longer mutate prior movement state. A dedicated regression reproduces that case.

The lazy viewer provides first-person/top-down, play/pause,0.25–2× presentation speed, bounded asynchronous seeks, timeline markers, local import/export and I9 moment seeking. Its renderer cannot attach or overwrite authoritative target history. Actual viewer checks pass15 browser cases/four layouts, with85 WebGL draws retaining authority checksums. Top-down framing/cutaway is display-only. **The viewer is currently silent**; no audio playback parity is claimed. See STAGE3_A2_VIEWER.md/JSON and screenshots.

Files: new `engine/replay/{types,integrity,recording,playback,validation,codec}.ts`; RenderedTargets provenance hook, RangeRenderer record suppression/inspection camera, cheap Movement jump serial and stable input sample; Runtime lifecycle; SessionData/history bounds; lazy ReplayViewer/transport/SessionReplay and Results/History integration.
