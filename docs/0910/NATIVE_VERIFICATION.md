# Landing sound: native verification remains open

The user's requested release scope is regression/performance/audio fixes plus
independent zoom sensitivity,360° count readouts and automatic graphics detection.
New courses/replay, sharing, crosshair-code parsing, stretched resolution, warmup
modes and English localization are deferred by the user's explicit scope choice.

The current execution environment does not contain a runnable native VALORANT PC
client. No first-party controlled comparison of walking+Space input, descent height,
landing velocity, standing/crouching and emitted landing sound was performed.
Public browser trainer behavior or a community description does not establish all
native rules. Therefore this update does not silently grant a quiet landing merely
because Shift is held. Existing original impact sounds and bot hearing remain
consistent with the disclosed trainer model.

Before changing that rule, capture permitted native-client evidence that records
walk/jump bindings, launch surface, apex/descent height, landing state and audible
output for repeated matched trials. Compare walking-only, jump-only, combined
walk+jump and high falls; test both launch/landing walk changes. Calibrate any quiet
threshold from that evidence and apply the same event policy to player audio and
sound-aware bot perception. No native parity or silent-jump correctness is claimed.
