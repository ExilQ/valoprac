# CPU·GPU·메모리 최적화 (12.39)

작성일: 2026-11-28

## 1. 측정 방법과 한계

- **브라우저와 GPU**: Chromium의 소프트웨어 GPU(SwiftShader)에서 측정했습니다. 이 환경에는 실제 그래픽카드가 없습니다.
  - 그래서 GPU 부하는 CPU 사용량과 그리기 호출(draw call) 수로 대신 봤습니다.
  - 실제 그래픽카드에서의 절대값은 다르지만, 줄어드는 비율은 같은 방향입니다.
- **VRAM**: WebGL 호출(텍스처, 버퍼, 렌더버퍼 할당)을 가로채서 추정했습니다. 화면 자체의 프레임버퍼는 브라우저가 따로 할당하므로 포함되지 않습니다.
- **CPU**: Chromium 전체 프로세스의 CPU 시간과 메인 스레드 사용 시간(CDP `Performance.getMetrics`)으로 쟀습니다.
- **해상도**: 1366×768에서 쟀습니다. 소프트웨어 GPU로 감지되어 "낮음" 품질이 자동 적용된 상태입니다.
- **그림자 측정**: "중간" 품질로 장면을 직접 그려서 쟀습니다(640×360).

## 2. 무엇이 자원을 쓰고 있었나

측정해 보니 JS 계산은 전체의 1% 미만이었습니다. 부하의 대부분은 다음 두 가지였습니다.
- 그리기(그래픽)와 화면 합성
- 멈춘 화면을 계속 다시 그리는 일

| 상황 | 문제 |
|---|---|
| 훈련 준비·일시정지 화면 | 아무것도 움직이지 않는데 3D 장면을 매 프레임 다시 그림. 그 위의 흐림 배경도 매번 다시 계산됨 |
| 메뉴 3D 미리보기 | 멈춘 장면을 초당 30번 그림 |
| 멈춘 리플레이 | 매 프레임 다시 그림 |
| 그림자 | 아무것도 움직이지 않아도 그림자 지도를 매 프레임 다시 그림. 정지한 건물 약 25개를 하나씩 따로 그림 |
| 캐릭터 데이터 | 움직이지 않아도 매 프레임 GPU로 다시 보냄 |
| 오디오 | 소리가 없을 때도 게임·효과음 오디오 스레드가 계속 돎 |
| 화면 정보(HUD) | 일시정지 중에도 초당 11번 다시 그림 |

## 3. 바꾼 것과 결과

### 3.1 멈춘 화면은 바뀔 때만 그리기

| 상황 (낮음 품질) | 이전 CPU | 12.39 CPU | 메인 스레드 | 그리기 호출/초 |
|---|---|---|---|---|
| 메뉴 | 0% | 0% | 0% | 0 |
| 훈련 준비 화면 | 136% | 12% | 99% → 5% | 1,493 → 54 |
| 일시정지 | 124% | 0% | 99% → 4% | 1,641 → 52 |
| 메뉴 3D 미리보기 | 초당 30번 그림 | 바뀔 때만 | 7% | 33 |
| 훈련 중 | 변화 없음(매 프레임 그림) | 같음 | — | — |

**동작 방식**
- 멈춘 화면은 다음 경우에만 다시 그립니다. 그 밖에는 5초에 한 번 안전용으로 다시 그립니다.
  - 설정 변경, 창 크기 변경, 무기 교체, 칼 스킨, 적 강조 색, 언어 변경
  - 이동 연습 도구 동작, 재시작
- 멈춘 동안에는 그리기 루프가 매 프레임 돌지 않고 0.05초마다 확인만 합니다. 다시 시작하면 즉시 매 프레임 그리기로 돌아갑니다.
- 성능 표시(FPS, 지연 상위 5%)는 실제 훈련 프레임만 계산합니다. 멈춘 동안의 프레임이 섞이지 않습니다.

### 3.2 그림자 ("중간" 품질, 1초 동안)

| 장면 | 이전 그림자 갱신 | 12.39 | 프레임당 그리기 호출 |
|---|---|---|---|
| 사격장, 표적 정지 (144Hz) | 144번 | 1번 | 79 → 54 |
| 사격장, 표적 이동 (144Hz) | 144번 | 60번 | 79 → 59 |
| 전술 맵, 봇 이동 (144Hz) | 144번 | 60번 | 79 → 61 |
| 사격장, 표적 이동 (60Hz) | 60번 | 60번 | 79 → 66 |
| 복합 훈련장, 봇 이동 (60Hz) | 60번 | 60번 | 91 → 72 |

- **필요할 때만 갱신**: 캐릭터나 봇 무기가 실제로 움직였을 때만 그림자 지도를 다시 그립니다. 고주사율에서도 초당 최대 60번입니다.
  - 60Hz 이하 화면에서는 이전처럼 매 프레임 갱신됩니다.
  - 설정을 바꾸면 그림자를 즉시 다시 그립니다.
- **정지한 건물 합치기**: 그림자를 드리우는 정지한 건물을 위치 정보만 가진 메시 하나로 합쳤습니다.
  - 이 메시는 그림자 계산에만 쓰이고, 화면 그리기에는 쓰이지 않습니다.
  - 그림자를 끈 품질("낮음")에서는 만들지 않아 메모리를 쓰지 않습니다.
- **화면 동일성 확인**: 같은 장면을 합친 그림자와 원래 방식으로 각각 그려 비교했습니다. 사격장, 전술 맵, 복합 훈련장에서 다른 픽셀이 0개였습니다.

### 3.3 GPU로 보내는 데이터

- 캐릭터 부위와 봇 무기 위치는 바뀐 것만 GPU 버퍼에 다시 씁니다. 이전에는 매 프레임 전부 보냈습니다.
- 표적이 서 있는 동안에는 업로드가 0입니다(테스트로 확인).

### 3.5 화면 정보

일시정지 중에는 화면 정보(HUD) 갱신을 초당 11번에서 2번으로 줄였습니다. 버튼 등으로 값이 바뀌면 즉시 갱신합니다.

## 4. 메모리 현황 (참고)

| 항목 | 크기 | 비고 |
|---|---|---|
| 텍스처 (낮음 / 중간 / 높음) | 2.8 / 7.6 / 약 32 MB | 높음의 절반은 그림자 지도 2048²(색 16MB + 깊이 16MB) |
| 정점·인덱스 버퍼 | 1.3 MB | |
| 소리 (전 무기) | 약 12.6 MB | 워커가 미리 만들고 전송(복사 없음) 후 종료 |
| JS 힙 | 15~25 MB | |

메모리가 가장 많이 드는 것은 사용자가 고르는 설정입니다.
- 그림자 품질 "높음"·"울트라"는 그림자 지도에 32MB를 씁니다.
- 안티앨리어싱은 화면 해상도에 비례해 프레임버퍼를 씁니다(1440p에서 약 100MB).
- 블룸과 앰비언트 오클루전은 HDR 화면 버퍼를 추가로 씁니다(1366×768에서 약 120MB).

그래픽 설정의 "낮음"이나 FPS 제한을 쓰면 GPU 사용량이 더 줄어듭니다.

## 5. 바뀌지 않은 것

- 훈련 중의 프레임레이트 정책(무제한 또는 사용자가 정한 제한)과 입력 지연은 그대로입니다.
- 시뮬레이션, 리플레이, 게임 규칙은 바뀌지 않았습니다.
- 훈련 화면은 픽셀 단위로 같습니다.
