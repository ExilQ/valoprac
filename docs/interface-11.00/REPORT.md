# VALOPRAC 11.00 — Precision Utility

## Scope and baseline

This is an incremental presentation release of the existing application. The
reference is production 10.00, source
`479cebefad88d00670cb5aba98df68232107de8b`. The interface was inspected and
captured from that frozen checkout before changing it. No Riot artwork, weapon
images, fonts, map assets, external font requests, or tracking services were added.

The main defects, in priority order, were:

1. Too many equally prominent destinations and a start action below the first
   desktop viewport. The baseline had 13 primary navigation items. The start
   button bottom was 1206.9 px at 1280×720 and 1213.3 px at 1366×768.
2. A nearly black menu palette, small secondary labels, and inconsistent control
   styling across settings, weapons, research, results, and static guides.
3. Settings distributed across a long form, large repeated selection panels,
   and detailed results competing with primary measurements.
4. HUD details that could not be operated while pointer lock was active, and
   insufficient separation between essential combat information and diagnostics.
5. Existing Korean wrapping, native dialog sizing, keyboard binding focus, and
   theme transition cases that needed explicit regression checks.

Darkness and visual comfort are design judgments, not results of a human study.
The baseline was not claimed to fail every accessibility criterion. Measured
layout and contrast results are reported separately below.

## Design and implementation

The original identity uses warm neutral surfaces, teal selection marks, aligned
measurements, restrained corners, and compact lists. Light is the default;
carefully authored dark and system preferences remain available. Theme storage
is independent of gameplay settings, and changing it does not recreate the
runtime or reset a session. Korean is the product interface language. A legacy
localization API is retained for data and replay compatibility; it is not an
English interface selector.

`src/ui/tokens.css` owns palette, typography, spacing, control borders, and motion
tokens. `scripts/sync-interface-tokens.mjs` generates the same tokens and theme
bootstrap for static guides. `precisionUtility.css`, scoped home, settings,
weapon, analytics and HUD sheets provide the presentation layer over existing
functional layouts. System Korean fonts avoid a new font download. Numerical
measurements use tabular figures. Text keeps Korean words together.

The six primary destinations are training, maps, weapons, sensitivity research,
history, and settings. Training is grouped into compact rows with an obvious
selection, relevant quick controls, a primary start action, and the actual 3D
preview below. All existing modes and advanced configuration remain available.
The collapsible mode list preference is preserved. All four weapons use original
silhouettes and a shared inventory layout with real configuration values.

Settings have eight categories. Existing controls and saved configuration remain
intact. Key binding fields pass Tab to the next control rather than rebinding it.
Reusable buttons, panels, and tabs live in `components/utility/Controls.tsx`;
tabs support arrow keys, Home, and End. Reduced motion is respected.

HUD instruments use their own stable dark palette over both bright and dark
environments. Essential information remains visible; detailed diagnostics are
optional. A paused inspection mode unlocks the pointer so native disclosures can
be opened without advancing simulation. Escape returns to pause controls.
Results show key metrics first and retain detailed analysis in a disclosure.
Research, charts, replay controls, patch notes, guides and the real HTTP 404 page
use the same interface foundations. The patch dialog has a bounded grid with a
scrolling history and visible header, filters, footer, and closing control.

Important implementation files include `App.tsx`, `MainMenu.tsx`, `MapLibrary.tsx`,
`SettingsPanel.tsx`, `AdvancedSettings.tsx`, `WeaponSelection.tsx`, `GameStage.tsx`,
`GameHUD.tsx`, `FootstepHUD.tsx`, `Results.tsx`, `History.tsx`, aim components,
`TrainingPlatform.tsx`, `ExerciseTraining.tsx`, `PatchNotes.tsx`, theme utilities,
`public/precision-docs.css`, and `worker/index.js`. The commit diff is the complete
file inventory.

## Preservation

No movement, recoil, ballistics, hit registration, bot decision, map collision,
footstep, sensitivity optimizer, or deterministic replay algorithm was changed.
Release/package version is **11.0.0 / 11.00**. The gameplay compatibility constant
intentionally remains **10.0.0**, and the simulation version remains
`valoprac-replay-simulation-2`. This preserves replay imports, sensitivity
history grouping, and personal records from 10.00.

A replay generated by the actual frozen 10.00 checkout is checked into
`src/tests/fixtures/replay-10.0.0.json`. The current engine reconstructs its 360
ticks, one shot, zero hits and checksum `272d8e5dcbf22345`, including after menu
theme changes. No fixture was relabeled as a newly measured human session.

## Visual comparison and release

`/interface-comparison.html` provides genuine 1366×768 before/after screenshots
of the main menu, selection, weapons, bright/dark HUD, settings, sensitivity lab,
history, results, patch notes and training tools, plus optional dark examples.
Full-page length is preserved. These are original, unretouched captures. Delivery
uses lossless WebP: all decoded RGBA pixels are checked against the original PNG,
and both file hashes are retained. The 27 images total 2,437,144 bytes at this
measurement, versus 4,962,515 bytes in PNG. Optional comparison binaries are not
duplicated inside the downloadable Unreal staging source ZIP; the source
repository and separate comparison page retain them. Results
use a repeatable simulated fixture, not human performance data. The original
file hashes and baseline provenance are in `SCREENSHOTS.json`.

All comparison images are optional, lazily loaded content and are not part of
the initial training download. Build and transfer measurements are recorded in
`BUILD_SIZE.json` and the final deployment receipt. The production 10.00 initial
load baseline was 451,317 encoded bytes in 18 resources; its complete JS/CSS
chunks were 2,324,388 raw / 692,888 gzip bytes. Neither is a new 11.00 measurement.

The exact pushed commit and locally built Worker are published through the
existing Sites workflow. Existing public access is retained. Production success
requires checking the live version, matching assets, HTTP security headers,
routes, theme controls and comparison content after deployment. A receipt is
recorded separately; this pre-publication source report does not assert that a
deployment has already succeeded. Rollback is the verified 10.00 saved version
23, source `479cebefad88d00670cb5aba98df68232107de8b`.

## Limits

No human usability study was conducted (participants: zero). Faster learning,
subjective comfort, native VALORANT parity, physical mouse counts, integrated
GPU performance, high-refresh behavior and physical input latency are not
claimed as verified. Unknown user-generated text and every possible extension
of stored data cannot be guaranteed by finite layout samples. Current evidence
supports the tested contrast, navigation, layout, keyboard and compatibility
claims. Existing mechanical calibration limitations remain in their original
reports.
