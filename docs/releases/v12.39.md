# VALOPRAC 12.39 — CPU·GPU·메모리 사용량 최적화
2026년 11월 28일 · 성능 패치

CPU, GPU(그래픽카드), 메모리를 덜 쓰도록 최적화했습니다. 훈련 중 화면은 픽셀 단위로 그대로입니다.

## 멈춘 화면은 바뀔 때만 그리기

이전에는 훈련 준비 화면과 일시정지 화면에서도 3D 장면을 매 프레임 다시 그렸습니다. 이제 설정·창 크기·무기 등이 바뀔 때만 다시 그립니다.

| 상황 | CPU | 그리기 호출/초 |
|---|---|---|
| 훈련 준비 화면 | 136% → 12% | 1,493 → 54 |
| 일시정지 | 124% → 0% | 1,641 → 52 |

- 메뉴의 3D 미리보기도 초당 30번 그리던 것을 바뀔 때만 그립니다.
- 멈춘 리플레이도 바뀔 때만 다시 그립니다.
- 다시 시작하면 즉시 매 프레임 그리기로 돌아갑니다.

## 그림자

- 캐릭터가 움직일 때만 그림자를 다시 그립니다. 고주사율 모니터에서도 초당 최대 60번만 갱신합니다.
- 움직이지 않는 건물의 그림자는 하나로 합쳐 한 번에 그립니다.
- 프레임당 그리기 호출("중간" 품질): 79회 → 54회(표적 정지), 59~61회(움직임, 144Hz)
- 합친 그림자와 원래 방식으로 각각 그린 화면을 비교해, 다른 픽셀이 0개인 것을 확인했습니다.
- 그림자를 끈 "낮음" 품질에서는 합친 메시를 만들지 않아 메모리를 쓰지 않습니다.

## GPU 데이터와 오디오

- 캐릭터·봇 무기 위치는 바뀐 것만 GPU로 보냅니다.
- 일시정지 중에는 게임 오디오 처리를 멈춥니다.
- 메뉴 효과음 오디오는 4초 동안 쓰지 않으면 멈추고, 다음 클릭에 다시 켜집니다.
- 일시정지 중 화면 정보 갱신을 초당 11번에서 2번으로 줄였습니다.
- 성능 표시(FPS)는 실제 훈련 프레임만 계산합니다.

## 측정과 한계

자세한 측정 결과는 `docs/PERFORMANCE_12.39.md`에 있습니다.
- 측정 환경에 실제 그래픽카드가 없어, 소프트웨어 GPU에서 CPU 사용량과 그리기 호출 수로 측정했습니다.
- 메모리를 가장 많이 쓰는 것은 그림자 품질 "높음" 이상, 안티앨리어싱, 블룸 같은 설정입니다. 그래픽 "낮음"이나 FPS 제한을 쓰면 더 줄어듭니다.

## 검증

- 애플리케이션 테스트, hosting 테스트, broker 테스트 전부 통과
- 타입 검사, 전체 빌드 검증 체인(`pnpm build`) 통과
- 새 테스트
  - 멈춘 화면 그리기 규칙
  - 일시정지 오디오
  - 캐릭터 데이터 변경 감지
  - 메뉴 효과음 오디오 정지·재개
- 실제 브라우저에서 확인한 것
  - 일시정지 → 재개 → 다시 그리기
  - 3D 미리보기와 일시정지 화면 표시
- 게임 규칙과 리플레이는 바뀌지 않았습니다.
